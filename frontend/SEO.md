# SEO setup

This site is a Vite + React SPA that is **prerendered to static HTML at build
time**. Crawlers that do not execute JavaScript — Facebook, WhatsApp, LinkedIn,
Bing, and most AI crawlers — receive the complete page, not an empty `<div id="root">`.

## How a build works

```
npm run build
  1. vite build                 -> dist/            (client bundle + assets)
  2. vite build --ssr           -> dist-ssr/        (server bundle, build-time only)
  3. node scripts/prerender.mjs -> dist/<route>/index.html
                                   dist/404.html
                                   dist/sitemap.xml
                                   dist/robots.txt
```

Step 3 renders the real React tree for every route with React 19's `prerender`
API (which, unlike `renderToString`, waits for `lazy()` and Suspense to settle),
then injects it plus a fully populated `<head>` into the built HTML template.

The browser still runs `createRoot()` — not `hydrateRoot()` — so the client
behaves exactly as before and there is no risk of hydration mismatches from
framer-motion. The static markup is for crawlers and first paint.

## Adding or changing a page

**`src/seo/seo.config.js` is the single source of truth.** Adding a route to
`App.jsx` is not enough — add it to `ROUTES` as well, or:

- it will not be prerendered,
- it will not appear in `sitemap.xml`,
- and it will return **404 in production** (there is no SPA catch-all in
  `.htaccess`; that is deliberate, so unknown URLs get a real 404 instead of a
  "soft 404").

Titles should stay ~50-60 characters and descriptions ~150-160.

## Files

| File | Purpose |
|---|---|
| `src/seo/seo.config.js` | Business details + per-route title/description/OG image |
| `src/seo/jsonld.js` | schema.org structured data builders |
| `src/seo/head.js` | Turns a route into the exact set of head tags |
| `src/components/Meta/Meta.jsx` | Applies the same head data on client-side navigation |
| `src/entry-server.jsx` | Build-time render entry |
| `scripts/prerender.mjs` | Writes the static HTML, sitemap and robots.txt |
| `scripts/make-og-images.mjs` | Regenerates `public/og/*` (1200x630 share images) |
| `scripts/serve-dist.mjs` | Serves `dist/` the way Apache does — use this, not `vite preview` |
| `public/.htaccess` | Canonical host, 301s for retired URLs, real 404s, caching |

## Social share images

`public/og/*.jpg` are generated by `npm run og` from `src/assets`.

They must live in `public/`, **not** `src/assets`: Vite content-hashes anything
imported from `src`, so the URL changes on every rebuild and breaks previews
already cached by Facebook and WhatsApp. `public/` URLs are stable.

Re-run `npm run og` only if the source photos change.

## Checking your work locally

```
npm run build
npm run serve:dist        # http://localhost:4173 — mirrors Apache
```

`vite preview` rewrites every unknown path to `index.html`, which hides routing
mistakes. `serve:dist` does not.

## After deploying

- Google Search Console — verify the domain, submit `https://hhhdesignstudio.com/sitemap.xml`
- Bing Webmaster Tools — import from Search Console
- Google Business Profile — the biggest single win for local searches
- Re-scrape share previews: Facebook Sharing Debugger, LinkedIn Post Inspector
- Validate structured data: <https://search.google.com/test/rich-results>

## Known gaps

- The project and blog listings load from the API in the browser, so their
  cards are not in the static HTML. Google renders them; non-JS crawlers do not
  see them. Fetching that data at build time would close the gap.
- `public/HHH Design Studio-1.pdf` is ~61 MB, unlinked, and ships with every
  deploy. It is blocked in `robots.txt`; compress or remove it.
- `npm run lint` reports pre-existing `no-unused-vars` false positives for JSX
  identifiers (`motion`, icon components). Adding `eslint-plugin-react`'s
  `jsx-uses-vars` rule would clear them.
